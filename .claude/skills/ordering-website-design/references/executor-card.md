# Executor card

The rules to edit this repo's UI without reading the whole skill. Read [SKILL.md](../SKILL.md) and the reference that applies when something is not covered here.

1. **Where.** Only `src/ui`, `src/pages`, `src/components`. Never the submodule `src/@/components`, `product.schema.json` or `src/theme.compiled.json`. Deep imports only, never the barrel.
2. **The theme decides.** Every value comes from the helpers of `docs/THEMING.md` §3: no hex, px, ms or font name. Keep precedence, `themeVisible`/`themePages` and what a store saved; a stored value that fails AA (3:1 for focus ring and field border) is reported (store, key, value, pair, ratio), never changed.
3. **Piece or legacy.** A control with a base piece (the table "The pieces" of design-system.md) uses the piece; a control without one keeps its legacy primitive of `src/ui/src/styles/` (never a native `<button>`) and is listed as a migration gap. Do not mix legacy and base controls of the same type in one visual group. A fix that changes no look stays legacy. Read the piece's source for its props.
4. **`ui:` only inside `design-system/components/`.** A screen composes with styled-components and `var(--ot-*)` or the helpers. Never `styled(Piece)`, and never CSS of a container that targets a piece (`[data-slot`, `--ui-*`). Never import `@base-ui/react` or `lucide-react` in a screen.
5. **Icons.** The base `Icon`; in the entry chunk (header, order context, chevron) `createIcon` with its glyph map in `components/Icon/<control>Glyphs.js`. A size only from the theme. One control never mixes legacy and base icons.
6. **A button of a theme slot.** Note the slot, its state condition and its mobile slot; for a base `Button` take the options with `slotButtonOptions` (`src/utils/themeGroups.js`).
7. **A value with no token (TOKEN-GAP).** In order: not a design value (comment why) > a property of the component > a token by name > a literal that is not a level goes through `docs/design-system/px-map.md` (approved, D1; write `No design decision: px-map`, never choose between two equally close levels) > otherwise the closest token marked `TOKEN-GAP(<issue>)` and listed (a tie between two levels is listed, not decided). Never a new token name.
8. **Design decision.** If the customer could see more than one reasonable result, stop and present 2 options that differ in what Sergio chooses. A same-value token swap, restoring main's look or a request that only names a theme value is `No design decision: <reason>`. Use `impeccable` and `frontend-design` in all visual work above N0.
9. **Accessibility floor.** Name on every icon-only control; visible focus that returns to the opener; Esc closes only the top layer; 44×44 px touch area for every interactive control, with its themed painted size; 16 px text in fields on a phone; reduced motion through the theme. The piece's floor is not the screen's verdict: check the integrated control.
10. **Guards.** `pnpm design:check` and `pnpm design:ratchet --base <the branch you started from>` green before handing back. A file outside the baseline may have zero findings. When your change removes findings, run `pnpm design:baseline` in a separate last commit; never by hand, never upward, never rewrite a literal to hide it.
11. **Verification.** Level N0 to N3 as the task says ([SKILL.md](../SKILL.md#verification)); computed-style assertions in 2 themes at least; show a gate you rely on red; say what you did not measure.
12. **Hand back.** Level; parity table or link; design decision or `No design decision: <reason>`; helpers used; each `TOKEN-GAP`, new schema setting, failing stored value and migration gap; states covered; files you moved; guard results; what was not measured.
